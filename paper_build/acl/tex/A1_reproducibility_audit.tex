\section{Appendix A1 --- Reproducibility Audit (per-agent)}\label{appendix-a1-reproducibility-audit-per-agent}

For each of the eight evaluated published systems, we attempted to reproduce
at least one point estimate from the agent's primary publication under a
comparable setup; the table explicitly marks partial or failed matches rather
than treating all attempts as successful. We treat a setup as \emph{successfully
re-instantiated} when our point estimate falls within \ensuremath{\pm}5 absolute
percentage points of the paper-claimed number on a comparable input
distribution (HPO-only vs free-text, top-1 vs top-5, EN vs zh). We
audit each agent on three axes:

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\tightlist
\item
  Faithful re-instantiation --- did we wire the agent's stack
  correctly?
\item
  Paper-claim replication --- does our number match the upstream
  number within the band?
\item
  Documented deviation --- what specifically did we change, and
  why?
\end{enumerate}

\textbf{Three documentation surfaces} for an independent re-runner:

\begin{itemize}
\tightlist
\item
  \texttt{data/round2/phase4a\_receipts.csv} --- 93-row legacy per-cell receipt:
  (dataset, agent, backbone, n\_ok, n\_err, R@1\_strict, R@1\_variants,
  R@5\_strict, R@5\_variants, cost\_usd, mean\_lat\_ms). Refreshed at every
  report regeneration. Its 22 legacy MIMIC rows are excluded from current
  claims. The committed \texttt{audit\_frozen/frozen\_main\_manifest.csv} is the
  evidence index for the 71 diagnostic cells used in the headline matrix plus
  12 temporally stratified PMC cells; the replacement MIMIC task will use a
  separate versioned receipt.
\item
  \texttt{docs/baseline\_repro/\textless{}agent\textgreater{}.md} --- per-baseline reproduction doc: upstream code source, license, paper-claimed numbers, our
  observed numbers, behaviour-changing patches (if any), known
  incompatibilities, and run receipts, one per agent plus the LLM
  control.
\item
  \texttt{tasks/stream\_E\_agent\_scouting/agents/\textless{}agent\textgreater{}\_RUN\_REPORT.md} ---
  \textbf{per-agent verbatim subprocess invocation} and parsed-output
  schema, captured at scout time.
\end{itemize}

The pilot numbers in the audit table below are from the N=50 scouting
pass that originally locked our agent lineup; the full-N point
estimates that headline the paper are in \Cref{sec-6} Main Results.

\subsection{Two agents underperform their paper claim --- both explained as input-distribution mismatch}\label{two-agents-underperform-their-paper-claim-both-explained-as-input-distribution-mismatch}

\textbf{MAI-DxO} is designed for narrative-rich NEJM-style case reports. Our
input is the CanonicalCase HPO-list + brief vignette. The panel's ``ask
the patient questions'' channel becomes degenerate on inputs that
already contain the answers; in early runs the panel began emitting
\emph{measurement values} (DLCO, LVEF, FEV1, FVC) as top-1 candidates. We
added a 13-pattern noise filter (\texttt{harness/agents/maidxo.py:\_NOISE\_PATTERNS})
to suppress non-diagnosis outputs and report the conservative
HPO-input number in \Cref{tbl:main}. We surface the input-distribution
mismatch openly (\Cref{sec-7-2} + \Cref{sec-9} L4).

\textbf{DeepRare} is designed for HPO + VCF input. On P2 (HPO-only),
DeepRare scores 0.22 R@1 --- near the LLM-control baseline. On
\textbf{P3 (HPO + structured variants, \Cref{sec-7-3}), DeepRare reaches R@1 = 0.42 (38/50, 95 \% CI {[}0.26, 0.58{]})} --- a +20 pp lift over its
own P2 number, but the same lift the single-LLM control receives from the same variants block (P3 = 0.46 vs P2 = 0.26). The gap
to the paper's claimed 0.706 (HPO+VCF) is \textasciitilde28 pp, attributable to
three setup differences we surface honestly: (a) our variants are a
structured-text block, not a real VCF integrated through DeepRare's
Phenotype Tool; (b) we disabled web search (\texttt{DEEPRARE\_NO\_WEB=1})
for contamination control, which the paper enables; (c) Phenopacket-
Store is a harder mixed-difficulty corpus than DeepRare's own
curated evaluation set. Our headline claim is therefore the weaker but more defensible ``variant channel adds \textasciitilde20 pp R@1 to any agent that ingests it'', not ``DeepRare specifically exploits
genotype-aware reasoning'' --- collapsing both into ``DDx accuracy''
would still miss the +20 pp lift, but the agent-specificity claim
does not survive contact with the LLM-control baseline.

\subsection{Bugs caught during audit (and the fix)}\label{bugs-caught-during-audit-and-the-fix}

We list four representative bugs we caught and fixed during the
reproducibility audit; our worklog retrospectives record the full set.

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\item
  Evaluator NL-fallback gap (Bug \#1, Retrospective \#3). Our
  \texttt{gold\_hit\_with\_crossmap} only matched cross-references by ID prefix.
  The Phenopacket-Store gold for \textasciitilde22 \% of cases lists OMIM + name but
  no ORPHA; predictions like \texttt{"Metachondromatosis"} (matching the gold
  \emph{name} but not its ID) returned \texttt{False}. We documented DeepRare
  at 0/50 R@1 in a draft table before catching this. Fix:
  case-insensitive name match + rapidfuzz fallback through Orphadata
  (threshold 90). 17 self-tests in
  \texttt{scripts/sanity\_check\_evaluator.py} now lock the behavior. Post-fix
  DeepRare scored 11/50 (0.22) on the same data.
\item
  DeepRare first-case state leak. DeepRare writes
  \texttt{result\_\textless{}tag\textgreater{}/\textless{}case\textgreater{}/\textless{}model\textgreater{}/patient\_0.json} with a deterministic
  \texttt{0} index. All 50 P2 cases returned the \emph{first} case's prediction
  (``Metachondromatosis'') on the first run. Fix: per-case unique
  \texttt{run\_tag\ =\ f"\{base\_tag\}\_\{case\_id{[}:40{]}\}\_\{suffix\}"} + defensive
  purge of the output directory before each call
  (\texttt{harness/agents/deeprare.py}).
\item
  GPT-5 reasoning\_effort silently consuming \texttt{max\_tokens}. See
  \Cref{sec-5-2} methods note. Five subprocess adapters had to be patched
  to propagate \texttt{OPENROUTER\_REASONING\_EFFORT=minimal} through the
  subprocess env.
\item
  Orphadata 53 MB XML re-parsed per call. After fixing Bug \#1 the
  NL-fallback path re-parsed Orphadata's 53 MB XML on every
  evaluator call, ballooning aggregation from \textless30 s to \textgreater30 min. Fix:
  \texttt{@lru\_cache(maxsize=1)} on \texttt{\_orphadata\_tables()}.
\end{enumerate}

\subsection{How a reader can independently re-run any cell}\label{how-a-reader-can-independently-re-run-any-cell}

For any \Cref{tbl:main} / \Cref{sec-6} cell \texttt{(agent,\ backbone,\ dataset)}, start from the
per-baseline reproduction doc, which sets expectations for the rerun,
then invoke the runner:

\begin{Verbatim}
python3 scripts/phase4a_runner.py \
    --dataset <phenopacket_store|rarearena_rds|rarebench> \
    --agent <baseline_name> \
    --backbone openrouter/<provider>/<model> \
    --n 100 \
    --out predictions_test.jsonl
\end{Verbatim}

The MIMIC structured-EHR probe is regenerated separately with
\texttt{scripts/build\_mimic\_early\_structured\_snapshots.py} and
\texttt{scripts/mimic\_structured\_ehr\_ablation.py}; protected row-level inputs are not
part of the public frozen diagnostic receipt.

\texttt{scripts/sanity\_check\_evaluator.py} must pass (\texttt{exit\ 0}) before any
number in the paper is trusted; this is enforced in our run harness.

\subsection{Cost transparency}\label{cost-transparency}

\texttt{scripts/cost\_tracker.py\ -\/-budget\ \textless{}USD\textgreater{}} prints the running per-backbone
cost from the prediction logs. The submission-time snapshot is in
Appendix J and the main-text cost-vs-accuracy figure.
